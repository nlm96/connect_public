## Summary of Likelihood Filter Module and User Guide
The sections below provide an overview of the CONNECT framework, the motivation for the likelihood filter module, its components, key parameters, and the outputs generated by the module. This information serves as a user guide for using the likelihood filter in cosmological parameter inference.
Additionally, one can also refer to the `example.param` file in the `connect/input` directory for an example of how to set up the likelihood filter parameters.

### **Overview of CONNECT**

CONNECT (***Co**smological **N**eural **N**etwork **E**mulator of **C**LASS using **T**ensorFlow*) is a neural network-based framework designed to drastically reduce computational costs in cosmological parameter inference. Traditional inference methods, such as Markov Chain Monte Carlo (MCMC) sampling, require millions of theoretical model evaluations using CLASS, which are computationally intensive. CONNECT addresses this challenge by using a neural network emulator trained on CLASS computations, which drastically reduces the computational costs.
This emulator predicts cosmological observables with high precision, significantly accelerating the inference process while maintaining accuracy.

---

### **Motivation for the Likelihood Filter**

#### **Iterative Sampling in CONNECT**

CONNECT's core functionality involves an **iterative process** to generate training data:
1. An initial dataset is created using Latin Hypercube Sampling (LHS) or Hypersphere Sampling.
2. CLASS computes cosmological observables for these points, forming the initial training set.
3. A neural network is trained on this data to emulate CLASS computations.
4. This trained neural network is then used as a **surrogate model** in an MCMC sampler to compute cosmological outputs and calculate the corresponding likelihoods.
5. The MCMC sampler generates new points in the parameter space. Only the last 
$N$ points from the MCMC chains are retained, and an overlap filter ensures these points are not too close to existing training data.
6. CLASS evaluates the retained points to produce the next training dataset.
7. Steps 3–6 are repeated iteratively to refine the emulator.

By using the neural network as a surrogate model during MCMC sampling, CONNECT dramatically reduces the number of CLASS evaluations. This iterative strategy gradually ensures efficient sampling in high-likelihood regions while gradually improving the emulator's accuracy.
As default, CONNECT discards all points from the initial sampling and the first iteration to avoid including "bad points" that could degrade the emulator's accuracy.

#### **Challenges and Limitations**

Despite its efficiency, the iterative process can lead to **inclusion of "bad points"**, which degrade the emulator's accuracy:
- The neural network, especially for complex models in early iterations, may misestimate the cosmological outputs leading to an inaccurate likelihood of certain points due to limited training data.
- Points with erroneously low predicted likelihoods may, in reality, have high likelihoods when evaluated by CLASS. These **"bad points"** can:
  - Misguide the MCMC sampler, causing it to explore less relevant regions.
  - Be included in the training data, expanding the neural network's output range to encompass irrelevant points.
  - Ultimately reduce the emulator's precision in high-likelihood regions, which are the primary focus of cosmological inference.

A simple but crude solution was to discard all points from the initial sampling and early iterations. However, this approach wastes potentially valuable samples.
It also fails to address the issue of "bad points" in later iterations for more intricate models. A more robust solution is needed.


---

#### **The Likelihood Filter Solution**

The **likelihood filter** addresses these challenges by focusing on likelihood values derived from the full CLASS-plus-likelihood-code pipeline, rather than relying solely on the neural network’s predictions. Although this pipeline uses fixed, non-optimized nuisance parameters, it still provides a more reliable baseline than the emulator’s “fake” likelihoods.

**"True" vs. "Fake" Likelihoods:**

- **"True" likelihoods**: Obtained by first running CLASS to produce theoretical predictions for a given set of cosmological parameters, and then passing these predictions to the likelihood code for evaluation. While the nuisance parameters remain fixed, this approach is still considered more accurate than the neural network approximation.

- **"Fake" likelihoods**: Quickly estimated using the neural network emulator. Although efficient, these predictions can be imprecise or inaccurate, especially in earlier iterations. 

Because the neural network sometimes assigns overly favorable (fake) likelihoods to certain points, these points may appear promising but actually perform poorly when checked against the true likelihood. Such misleading samples are termed **"bad points"**.

**How the Filter Works:**

- The filter compares each sample’s true (CLASS+likelihood-code) likelihood to that of the current global best-fit model (the one with the lowest -log(likelihood) found so far).

- It then computes each sample’s $ \Delta\chi^2 $ value:

  $$
  \Delta\chi^2 = 2 \times \bigl(\text{-log}(\mathcal{L}_{\text{sample}}) - \text{-log}(\mathcal{L}_{\text{best-fit}})\bigr),
  $$

  Here, $ \mathcal{L}_{\text{sample}} $ and $ \mathcal{L}_{\text{best-fit}} $ are the true likelihoods for the sample and the best-fit point, respectively.

- Any sample with $ \Delta\chi^2 $ exceeding a specified threshold $ \Delta\chi^2_{\text{threshold}} $ is considered a bad point and removed from the training data.  
(if $ \Delta\chi^2_{\text{point}} > \Delta\chi^2_{\text{threshold}} \Rightarrow $ discard the sample) 

By removing these bad points, the filter ensures that subsequent neural network training and parameter-space exploration focus on parameter regions genuinely supported by the data’s likelihood constraints, even without individually optimized nuisance parameters.

---

### **Components of the Likelihood Filter Module**

1. **Likelihood Calculator**:
   - Computes the "true" likelihoods of samples using CLASS instead of the neural network emulator.

2. **Likelihood Tracking**:
   - Tracks likelihood values together parallel its respective samples and cosmological outputs throghout the code. It stores both CLASS-computed and neural network-predicted likelihoods for each sample.
   - The tracked data is stored in a separate `likelihood_data.txt` file within each iteration folder and initial sampling folder, allowing post-processing and analysis. It is also this file that is used for the filtering process.
   `likelihood_data.txt` contains two columns: one for the "true" CLASS based likelihood values and one for the "fake" neural network-predicted likelihood values.
   Only the "true" likelihood values are used for the filtering process.
   Each row in `likelihood_data.txt` matches each sample's row in the corresponding training data files and is continuously updated throughout the iterations together with training data files as samples are removed from the training data.

3. **Likelihood Filter**:
   - Filters the accumulated training data at each iteration and during the initial sampling.
   - Ensures only high-quality samples contribute to the neural network training.
   - It iteratively removes points with poor likelihoods based on their $ \Delta\chi^2 $ values and the current iterations global best fit point. Thus, points that were previously accepted but are now considered "bad" are removed from the training data. This ensures the final converged neural network should be trained on high-quality samples only. But it might also improve the convergence, since the MCMC sampler will not get stuck in regions of parameter space that are not well-supported by the data.

---

### **Key Parameters**

The likelihood filter is controlled by the following parameters (set in the input parameter file for CONNECT):

- **`use_likelihood_filter`** (*bool*):  Enables/disables the likelihood filter.  
Default is `True`.
- **`delta_chi2_threshold`** (*float*): Specifies the $ \Delta\chi^2_\text{threshold} $ for discarding points.
    - Points with $ \Delta\chi^2 > \Delta\chi^2_\text{threshold} $ are removed.
    - This threshold controls the strictness of the filter. Lower values lead to more aggressive filtering.
- **`min_points_to_keep`** (*int*): Ensures a minimum number of points are retained after filtering, preventing insufficient training data. It stops the likelihood filter early if the number of retained points falls below this threshold. It is applied at every iteration, so it is the minimum number of training samples to be used in the neural network training at any given iteration. Currently default is 5000.
- **`discard_worst_first`** (*bool*): Determines whether to discard points with the highest $ \Delta\chi^2 $ first or sequentially (based on the order stored in the training data files), discarding older iteration points first. Default is `True`. Only relevant if `min_points_to_keep` becomes relevant.
- **`nuisance_params_lkl`** (*dict*): Specifies fixed nuisance parameter values for the likelihood calculator (only used by the likelihood filter module, not MCMC sampling). It is a dictionary with nuisance parameter names as keys and their fixed values as values. default: nuisance_params_lkl = {'A_planck': 1.0}, which can be used with Planck likelihoods.
The likelihood calculator uses fixed nuisance parameter values to ensure consistent likelihood calculations across all samples and iterations.
- **`keep_initial_data`** (*bool*): Retains/discards initial sampling data when using the likelihood filter. Default is `True`.  
Note: If `use_likelihood_filter` is `False`, this parameter is inactive, and all initial sampling data is discarded.
- **`keep_first_iteration`** (*bool*): Retains/discards data from the first iteration, independent of the likelihood filter's activation. Default is `True`. Note: If `use_likelihood_filter` is `False`, this parameter is still active and should be set to `False` if the first iteration data should be discarded. If `use_likelihood_filter` is `True` and `keep_initial_data` is `True`, `keep_first_iteration` is automatically set to `True`.

#### Thoughts on Parameters:
- `use_likelihood_filter`:
    - *It is crucial to have this parameter to easily enable/disable the likelihood filter without changing the code. This allows users to compare the results with and without the likelihood filter, and to test the impact of the filter on the training data. It is especially useful for research purposes.*
- `min_points_to_keep`:
    - *This parameter ensures sufficient training samples at every iteration. It might be beneficial to add a `min_points_to_keep_initial` parameter, since the initial sampling usually only samples 10000 points, and we probably want to keep more than 10000 points at the final iteration. However, it might still be beneficial to discard some of the initial sampling points, since it might speeds up the convergence, so in that case an extra parameter would be necessary.*
- `discard_worst_first`:
    - *The default assumption is that earlier iterations are more likely to contain worse points, and therefore prioritizing the worst likelihood points globally or filtering sequentially, most likely will not make a difference. However, in special cases, it might be beneficial to provide flexibility in the filtering process. Sequential filtering aligns with CONNECT’s iterative nature. However, it is set to `True` by default, since I presume that we always want to remove the worst points first, to ensure that the neural network is trained on the best possible samples in terms of likelihood.*
- `nuisance_params_lkl`:
    - *This is added, so the user manually can provide all the necessary nuisance parameters and their fixed values to be used by the likelihood calculator. We choose a fixed value since it effectively makes the likelihood values independent of the nuisance parameters; We are only interested in the relative likelihood of the samples and the global best fit point, not necessarily the optimized likelihood with the best nuisance value. This is a simple way to ensure that the likelihood values are calculated consistently across all samples and iterations.*
- `keep_initial_data`:
    - *This parameter was mainly added for research purposes. Ideally, we would want to keep the initial sampling, since the likelihood filter is designed to remove "bad points" from the beginning of the sampling. However, for research purposes, it might be interesting to see a direct comparison, iteration by iteration, with and without the likelihood filter, where they both start retaining the data after 1st iteration, as default for the no-likelihood filter case. This parameter probably should be removed in the final version.*

### **Outputs of the Likelihood Filter Module**

The likelihood filter module generates several outputs that document its operations and enable further analysis:


#### **1. Likelihood Data File**
- **`likelihood_data.txt`**:  
  This file is created in the corresponding iteration or initial sampling folder, located at:  
  - `connect/data/{jobname}/number_{iteration}` for iteration data.  
  - `connect/data/{jobname}/N-{N}` for the initial sampling.  

  **Contents**:  
  - Column 1: The "true" $-\text{log}\cal{L}$ values, computed using CLASS. These are used by the filter.
  - Column 2: The neural network-predicted $-\text{log}\cal{L}$ values.  (included for analysis but unused in filtering).



#### **2. Filtered Training Data Files**
The training data files are updated to reflect the filtering decisions. Points that exceeds the likelihood filter threshold are removed from the training data files, such as `model_params.txt`, `Cl_{type}.txt`, etc. Their locations are the same as the original training data files.

**Filtered Points**:  
Discarded points are saved in a subdirectory named `loglkl_discarded_data`, located in:  
`connect/data/{jobname}/number_{iteration}/loglkl_discarded_data` or `connect/data/{jobname}/N-{N}/loglkl_discarded_data`.

The subdirectory mirrors the original training file structure, enabling straightforward post-processing and analysis.


#### **3. Likelihood Calculator Files**
A dedicated folder, **`lkl_calc`**, is created to manage the likelihood calculator's operations. It is located at:  
`connect/data/{jobname}/lkl_calc`.

**Contents**:
- The folder contains input files (`likelihood_calc.param` for MontePython or `likelihood_calc.yaml` for Cobaya), logs, and auxiliary outputs needed for initializing and running the likelihood calculator.

Additionally, a `best_fit_point.txt` file is stored in the iteration folder, containing the -log(likelihood) value of the current global best-fit point and its corresponding parameter values. This file is logged only for post-processing and analysis purposes. It is not used by the filter itself.

## **Overview of Code Changes**

### **Summary of CONNECT’s Existing Codebase**

CONNECT’s iterative algorithm revolves around the `data_sampling.py` script, which coordinates key functions for sampling, filtering, evaluating, and training. The following functions/methods called in `data_sampling.py` are central to the process and relevant to the likelihood filter module:

#### **1. MCMC Sampling and overlap filtering**
- **`mcmc.run_mcmc_sampling(model, i)`**  
  Executes the MCMC sampler for the current iteration using the neural network model. This function resides in `source/mcmc_samplers/montepython.py` or `source/mcmc_samplers/cobaya.py`.
- **`mcmc.filter_chains(N_keep, i)`**  
  Retains the last $N_\text{keep}$ points from the MCMC chains. Also located in `montepython.py` or `cobaya.py`.
- **`mcmc.discard_oversampled_points(i)`**  
  Implements the overlap filter to discard points that are too close to existing training data. This function is found in `source/mcmc_base.py`.

#### **2. CLASS Evaluations**
- **`self.call_calc_models(sampling='iterative')`**  
  Calls the `calc_models_mpi.py` script to evaluate new points using CLASS. The process involves:
  1. Importing new points generated by the MCMC sampler via `mcmc.import_points_from_chains(iteration)` in `montepython.py` or `cobaya.py`.
  2. Evaluating these points using CLASS, distributed across MPI workers.
  3. Storing the computed training data in temporary subfolders and temporary files indexed by MPI rank.

#### **3. Data Management**
- **`create_output_folders(self.param, iter_num=i, reset=False)`**  
  Prepares temporary output folders to store computed training data for each MPI worker. This function is located in `source/tools.py`.
- **`join_data_files(self.param)`**  
  Merges the output files from all MPI workers into a single file for each type of data (e.g., model parameters, $C_\ell$ data, etc). This method resides in `source/tools.py` and calls `CreateSingleDataFile.join()` in `source/join_output.py`.
- **`combine_iterations_data(self.param, i)`**  
  Combines data from the current and previous iterations into a unified dataset for each file type. Found in `source/tools.py`.

#### **4. Neural Network Training**
- **`model = self.train_neural_network(...)`**  
  Trains the neural network on the combined dataset. This step occurs within the `data_sampling.py` script.

Additionally, there are also some convergence checks, that are not directly related to the likelihood filter, but are important for the overall algorithm of the iterative process. These checks stop the iterations if the convergence criteria are met.

### **Overview of Changes to the Existing Codebase**

To integrate the likelihood filter module, several modifications were made to CONNECT’s codebase. These changes ensure the seamless incorporation of likelihood tracking and filtering during the iterative process.

#### **Modified Files and Functions**
1. **`default_module.py`**  
   - Added parameters for the likelihood filter to the default configuration dictionary. These parameters are listed above in the "Key Parameters" section.

2. **`connect.py`**  
   - Updated to generate an input file used for initializing the likelihood calculator later in the iterative process.

3. **`tools.py`**  
   - Updated `create_output_folders()` to create temporary subdirectories for storing likelihood value data files for each MPI rank.
   - Modified `combine_iterations_data()` to also merge likelihood data from the current and previous iteration. Including an update to handle combining the initial sampling and first iteration data when the likelihood filter is active.

4. **`mcmc_samplers/montepython.py`**  
   - Added `import_loglkl_from_chains()` to extract -log(likelihood) values from MontePython chains. This method needs to be implemented in `cobaya.py` for Cobaya compatibility.

5. **`mcmc_base.py`**  
   - Extended core functionality list to include `import_loglkl_from_chains(iteration)`.

6. **`calc_models_mpi.py`**  
   - Introduced likelihood tracking and calculation:
     - Instantiates the likelihood calculator class. It does this once per worker and iteration.
     - Imports and processes "fake" -log(likelihood) values from MCMC chains.
     - Calculates "true" -log(likelihood) values using the computed CLASS object at each worker.
     - Updates worker behavior to manage likelihood values separately and store them in rank-specific files.

7. **`join_output.py`**  
   - Updated `CreateSingleDataFile.join()` to consolidate likelihood data files from different MPI ranks into a single file for each iteration and the initial sampling.

8. **`data_sampling.py`**  
   - Incorporated the likelihood filter into the iterative process by:
     - Applying the overlap filter (`discard_oversampled_points()`) between the initial sampling and the first iteration when the likelihood filter is active.
     - Modifying calls to `combine_iterations_data()` to accommodate the likelihood filter by combining the initial sampling and first iteration data.
     - Adding calls to the `LikelihoodFilter` class (`source/lkl_filter_module/likelihood_filter.py`) to apply filtering before training the neural network.

---

#### **New Classes and Methods**
To support the likelihood filter, the following classes and methods were added in a new directory, `source/lkl_filter_module`:

1. **`likelihood_filter.py`**  
   - Implements the `LikelihoodFilter` class for applying filtering logic based on $ \Delta\chi^2 $ values.

2. **`likelihood_calc_base.py`**  
   - Defines the `LikelihoodCalculator` base class, which MontePython and Cobaya-specific calculators inherit from.

3. **`likelihood_calc_montepython.py`**  
   - Contains the `MontePythonLikelihoodCalculator` class for calculating "true" likelihoods using MontePython.

4. **`likelihood_calc_cobaya.py`**  
   - Placeholder for the `CobayaLikelihoodCalculator` class (to be implemented).

---

#### **Configuration File**
A new configuration file, **`likelihood_calc.conf`**, has been added to the `source/lkl_filter_module` directory. This file contains paths for CLASS, MontePython, and clik, ensuring compatibility across environments. The `setup.sh` script was updated to create and manage this configuration file.

```python
    def adjust_defaults_based_on_likelihood_filter(self):

        Adjust default values of keep_initial_data and keep_first_iteration

                if 'keep_first_iteration' not in self.param_file:

        if self.keep_initial_data and not self.keep_first_iteration and self.use_likelihood_filter:
```

### `tools.py` Module Modifications

#### `create_output_folders()` in `tools.py`
`create_output_folders()` in the `tools.py` module creates various output folders for the iterative process. 
It specifically creates several temporary subfolders to store data files created by each MPI worker in `calc_models_mpi.py`. The modifications to this function now include creating a temporary subfolder, `likelihood_data`, to store likelihood data files, `likelihood_data_{rank}.txt`, for each MPI worker during the likelihood calculations.



#### import_loglk_from_chains() in montepython.py

**Description:**  
Implement a new method `import_loglkl_from_chains()` in the `montepython.py` module inside the `montepython` class. This method reads the -log(likelihood) values from the chain files generated by the MCMC sampler and returns them as a NumPy array.

**Chain File Structure:**  
Each chain file contains MCMC samples:
- **First column**: Stores multiplicity and -log(likelihood), separated by **two spaces**.
- **Remaining columns**: Cosmological parameters, separated by **tabs**.
- **Comment lines** (beginning with `#`) are skipped.

(In MCMC sampling, multiplicity represents how many times the chain remains at the same point in parameter space, meaning it "stays" at that position for multiple steps. This occurs when proposed steps are rejected, so the last accepted point is repeated in the chain, effectively increasing its multiplicity. A high multiplicity at a point can indicate a region where the chain is exploring parameter space slowly, potentially due to tight constraints or local maxima in the likelihood function.)

**Usage:**  
This method is used in `calc_models_mpi.py` to track likelihood values across samples for filtering purposes, specifically in implementing the likelihood filter based on the difference from the current best-fit point.

### `calc_models_mpi.py` Module Modifications

These changes integrate "true" likelihood computations into the MPI-based evaluation of cosmological models, ensuring that model parameters, cosmological outputs, and likelihood values are consistently computed and tracked in parallel and stored in rank-specific files. The modifications include the following key features:

**Key modifications:**

1. **Modular Likelihood Calculation**:  
   When using iterative sampling with the likelihood filter, the code dynamically imports and instantiates a `likelihood_calculator` (e.g., `MontePythonLikelihoodCalculator`). This calculator uses MontePython’s `Data` class and `compute_lkl(cosmo, data)` function to compute `-log(likelihood)` values. By leveraging MontePython’s infrastructure, we ensure compatibility with various likelihood codes configured in `data.experiments`.
   Cobaya compatibility is not fully implemented yet, but the code structure allows for easy extension to support Cobaya likelihood calculations, if it ends up having a similar structure to the MontePython based likelihood calculator class.

2. **Automatic CLASS Parameter Configuration**:  
   To align CLASS computations with the chosen likelihood code’s requirements, the code updates key cosmological arguments:
   - **`l_max_scalars`**: If the likelihood filter is used, `l_max_scalars` is set to match the value specified by the likelihood code (e.g., 2508 for Planck-lite) rather than relying on CLASS’s default (2500) or a user-defined setting. This ensures the computed CMB spectra meet the experiment’s resolution needs.
   - **`params.update(initial_cosmo_arguments)`**: On worker nodes, the code updates CLASS parameters with `initial_cosmo_arguments` extracted from MontePython’s `Data` instance. This step automatically applies any cosmological settings required by the likelihood (e.g., lensing, output types, other likelihood-specific parameters similar to `l_max_scalars`) without manual intervention, making the system more adaptable to different experiments.

3. **Synchronization of Parameters and Likelihoods**:  
   The master rank sends both model parameters and chain-based likelihood values (`loglkl_chains`) to each worker. With these inputs, each worker sets up CLASS, computes cosmological observables, and uses the calculator to determine the "true" likelihood (`loglkl_true`). By providing a precomputed `cosmo` instance to the calculator, we avoid costly recomputations.

4. **Rank-Specific Storage of Results**:  
   Each worker writes model parameters, cosmological outputs, and now likelihood values into rank-specific files. Alongside `model_params_{rank}.txt` and files for CMB spectra or matter power, a new `likelihood_data_{rank}.txt` file stores both `loglkl_true` and `loglkl_chains`. A clear header line distinguishes the two columns, streamlining post-processing and filtering steps.

5. **Future Compatibility and Flexibility**:  
   Initially developed for MontePython and Planck-lite, this approach should be capable of handling other likelihood codes with no adjustments. However, further testing may need to test if setting the CLASS instance based on `data.cosmo_arguments` is valid for other likelihood codes. The code structure anticipates future Cobaya integration, with a placeholder for the `CobayaLikelihoodCalculator` class. Once implemented, the code will be updated to include Cobaya-based likelihood calculations.

#### `LikelihoodCalculator` Base Class
This class serves as the base class for implementing likelihood calculators in CONNECT. The MontePython and Cobaya specfic likelihood calculators inherit from this base class. The base class provides a framework for initializing the likelihood calculator, setting parameters, and computing likelihood values. It also includes methods for saving configurations and handling exceptions during likelihood computation.
This class is inspired by PROSPECT's `base_kernel.py` module.

This base class has the loglkl() method that calculates the likelihood value for a given set of model parameters. It takes a prop object, which is a dictionary containing the model parameters, including fixed and varying parameters and nuisance parameters, that are used to compute the likelihood value. These parameter names uses CLASS parameter names as convention. 
It also takes a cosmo object, which is a CLASS instance containing the computed cosmological outputs. The loglkl() method calls the _loglkl() method, which should be implemented by the derived classes to compute the likelihood value.

```python	
class LikelihoodCalculator(ABC):
    """
    Abstract base class for implementing likelihood calculators. 
    Subclasses must implement methods for initialization, parameter setup, 
    and likelihood computation. This class serves as the framework for 
    modular integration with various MCMC samplers or likelihood codes.
    """
    def __init__(self, param_connect, task_id, output_folder=None):
        """
        Initialize the likelihood calculator.

        Args:
            param_connect: Object containing CONNECT configuration parameters.
            task_id: Identifier for the current task (e.g., MPI rank).
            output_folder: Directory to save any configuration or output files.
        """
        self.set_default_errors()
        self.id = task_id
        self.param_connect = param_connect  # Store the configuration for later use
        self.output_folder = output_folder
        self.initialise(param_connect, self.id)

        self.param = {
            'varying': {},
            'fixed': {},
            'derived': {}
        }
        self.set_parameter_dict()
        self.save_config()
    
    class NullException(Exception):
        pass

    def set_default_errors(self):
        """
            Two error types exist: 
                Severe exceptions will stop the process
                Computation exceptions will assign -inf as the 
                likelihood value of the proposed point and then continue the run

            Derivatives of BaseKernel can define their own specific error types.
        """
        # By default, all exceptions are severe
        self.severe_exception = Exception 
        self.computation_exception = self.NullException

    @abstractmethod
    def initialise(self, param_connect, task_id):
        pass

    def set_fixed_parameters(self, fixed_param_dict):
        for param_name, fixed_value in fixed_param_dict.items():
            # Move parameter to the fixed dict
            self.param['fixed'][param_name] = self.param['varying'][param_name]
            self.param['fixed'][param_name]['fixed_value'] = fixed_value
            del self.param['varying'][param_name]
    
    @property
    def varying_param_names(self):
        return list(self.param['varying'].keys())
    
    @abstractmethod
    def set_parameter_dict(self):
        """
            Must set self.param, a dict with keys that are parameter names
        """
        pass
    
    def save_config(self):
        """
        Saves kernel-specific data in the kernel subdir based on type
            - MontePython: .conf and .param
        """
        pass


    def loglkl(self, prop, cosmo):
        for fixed_param, param in self.param['fixed'].items():
            prop[fixed_param] = [param['fixed_value']]
        try:
            return self._loglkl(prop, cosmo)
        except self.computation_exception as e:
            print(f"Soft exception {e} occurred. Assigning inf to loglkl.")
            return np.inf
        except self.severe_exception:
            raise ValueError("Severe exception occurred in likelihood computation. Stopping process.")
    

    @abstractmethod
    def _loglkl(self, position):
        # Should return -log(likelihood); note the minus sign!
```

### `lkl_filter_module/likelihood_calc_montepython.py` module
The `likelihood_calc_montepython.py` module defines the `MontePythonLikelihoodCalculator` class (This class is inspired by PROSPECT's `montepython_kernel.py`), which leverages MontePython’s existing parameter and likelihood framework to compute cosmological likelihood values at a single parameter point. Unlike a full MCMC run, which iteratively explores parameter space and updates cosmological outputs at each step, this calculator focuses solely on evaluating the likelihood once given a precomputed cosmology and specific parameter sample. It reuses MontePython’s configuration, parameter handling, and likelihood evaluation routines, but operates in a more direct and controlled manner and without the overhead of re-running CLASS.

To understand how this integration works, it helps to follow the logical flow of the code step-by-step, starting from a call to `loglkl()` on the `MontePythonLikelihoodCalculator` instance, and tracing how parameters and data pass through the MontePython pipeline.

#### Initialization and the `Data` Instance

When a `MontePythonLikelihoodCalculator` is created, it sets up a MontePython environment similar to a standard MCMC run. This is done through the `InitialiseMontePython` singleton class in the same file. Internally, `InitialiseMontePython` invokes MontePython’s `initialise.py` module with a command like:
```bash
run -p likelihood_calc.param --conf likelihood_calc.conf -o ...
```
This setup reads the required `.param` and `.conf` files (`likelihood_calc.param` and `likelihood_calc.conf`) to configure the experiments and parameter settings.
This is essentially the same way you would start a MontePython run, except here we do not proceed with chain sampling. Instead, `initialise.py` creates a `data` object (as defined in `data.py` in MontePython’s source) and configures it just as if an MCMC run had begun.

The `data` object is the central repository for parameters and handling the experimental data and likelihood configurations. It contains:

- **`data.mcmc_parameters`**: An ordered dictionary of parameter names and their attributes (initial values, roles, scales, current values, etc.). For example:
  ```python
  data.mcmc_parameters['omega_b'] = {
      'initial': [0.022, None, None, ...],
      'scale': 1,
      'role': 'cosmo',
      'status': 'varying',
      'current': 0.022
  }
  ```
- **`data.cosmo_arguments`**: A dictionary of cosmological parameters that would be passed to CLASS (e.g., `omega_b`, `h`, `A_s`) after calling `data.update_cosmo_arguments()`. Under normal MCMC operation, MontePython would repeatedly modify `data.mcmc_parameters['...']['current']` at each new point in parameter space, call `data.update_cosmo_arguments()`, and then let MontePython’s internal machinery compute or update cosmological outputs before evaluating the likelihood. Here, we do the same parameter updating and `data.update_cosmo_arguments()` call, but we skip the internal CLASS computation, because we will supply a precomputed `cosmo` (CLASS) instance directly.

- **`data.lkl`**: A dictionary of likelihood instances, each corresponding to an experiment or dataset defined in the `.param` file. MontePython uses these likelihood instances to compute log-likelihoods given a cosmology.

In a full MCMC scenario, `data` is updated at each step, CLASS is run to compute the cosmology, and then the likelihood is evaluated. Here, we replicate the data structure and initialization but do not rely on MontePython to re-run CLASS. Instead, we provide a precomputed `cosmo` instance directly.

Importantly, the `data` object is only initialized once and subsequent calls or initializations of the `MontePythonLikelihoodCalculator` reuse the same initialization. This ensures the ´data´ object is only initialized once per worker (per sampling iteration), avoiding repeated setup overhead.

#### Calling `loglkl()`

To evaluate the likelihood at a given parameter point, we call `loglkl(prop, cosmo)` on the `MontePythonLikelihoodCalculator` instance. The `prop` argument is a dictionary of model parameters in CONNECT’s own naming convention (Or more precisely, CLASS naming convention).

``` python
prop = {
    'omega_b': [0.0225],
    'h': [0.68],
    ...
}
```
The `cosmo` argument is a CLASS instance already computed by CONNECT to produce cosmological observables (like CMB Cls) for these exact parameter values. This is `cosmo` instance is used by CONNECT to create the new training data for the neural network. Supplying a precomputed `cosmo` directly avoids rerunning CLASS within MontePython.

Inside `loglkl()`, defined in `likelihood_calc_base.py`, the code calls `_loglkl(prop, cosmo)`, which `MontePythonLikelihoodCalculator` overrides as _loglkl(position, cosmo). In `_loglkl()`, we translate the `prop`/`position` dictionary from CONNECT’s (CLASS) parameter names to MontePython’s parameter names using dictionaries like `self.connect_to_mp_name`, ensuring that parameters align with what the MontePython `data` object expects.
This translation was copied from PROSPECT's `montepython_kernel.py` assuming PROSPECT's parameter names are the same as CONNECT's/CLASS's. This should perhaps be looked further into.

Next, we update the `data` instance. For each parameter, we do:
```python
self.mp['data'].mcmc_parameters[<mp_param_name>]['current'] = position[<connect_param_name>][0]
```
If the parameter is varying, the new value is taken from `position`. If it is fixed, we assign its fixed value. Normally, this step ensures that if MontePython were to recalculate the cosmology during a chain step, it would produce a cosmology consistent with these parameters.

We then call:
```python
self.mp['data'].update_cosmo_arguments()
```
This synchronizes `data.mcmc_parameters` with `data.cosmo_arguments`, ensuring that `data.cosmo_arguments` reflects the latest parameter set. Under a full MCMC run, the next steps would be `cosmo.set(data.cosmo_arguments)` and `cosmo.compute()`, triggered by MontePython’s `compute_lkl()` function if `data.need_cosmo_update` is `True`.

However, we bypass this by manually setting:
```python
self.mp['data'].need_cosmo_update = False
```
This prevents MontePython from rerunning CLASS. Instead, `compute_lkl(cosmo, data)` will trust that `cosmo` is already consistent with `data.mcmc_parameters`.

#### Using `compute_lkl(cosmo, data)`
The _loglkl() method leverages MontePython’s `compute_lkl()` function to calculate the likelihood. 
The `compute_lkl()` function, found in `sampler.py`, orchestrates the likelihood computation. Under normal circumstances, it would:

1. Check `data.need_cosmo_update`. If `True`, run `cosmo.set(data.cosmo_arguments)` and `cosmo.compute()` to get a cosmology consistent with the current parameters.
2. Loop through each likelihood in `data.lkl`.
3. For each likelihood, call `loglkl(cosmo, data)`. Inside these likelihoods (defined in `likelihood_class.py` or in experiment-specific modules), methods like `self.get_cl(cosmo)` retrieve CMB power spectra or other observables from the `cosmo` instance.
4. Compare these observables to the experimental data and compute a log-likelihood.
5. Sum the contributions from all likelihoods and return the total log-likelihood, if multiple experiments are used.

Because `data.need_cosmo_update = False`, step (1) is skipped. `compute_lkl` uses the `cosmo` instance you provided as-is. 

Once `compute_lkl(cosmo, data)` returns the total log-likelihood, `_loglkl()` returns its negative value, and `loglkl()` passes that value on to the caller.

#### Are `data.mcmc_parameters['...']['current']` and `data.cosmo_arguments()` Updates Redundant?

Since we provide a precomputed `cosmo` that already corresponds to the parameter values in `prop`, one might argue that updating `data.mcmc_parameters['...']['current']` and calling `data.update_cosmo_arguments()` is redundant. After all, no CLASS call is made, and the likelihood classes will just use the Cls stored in `cosmo`.


However, `data` plays a broader role:

- Most likelihoods rely on nuisance parameters that are retrieved directly from `data.mcmc_parameters` at likelihood evaluation time. But since every call uses the same nuisance parameter values, the updates might appear uneccessary. But with the current implementation, we still needs to set the nuisance parameters' values in `data.mcmc_parameters` to ensure to ensure that the likelihoods can access them.

- Similarly, if future modifications or different likelihoods need to check parameter values from `data` (beyond just nuisance parameters) or even beyond cosmological parameters, these updates should guarantee that everything in `data` matches the `cosmo` object you provide.
  
While it may appear redundant now—especially if nuisance parameters are fixed and the `cosmo` instance is perfectly matched to the parameters—updating `data.mcmc_parameters` and `data.cosmo_arguments` maintains a stable and predictable interface. It ensures that `compute_lkl(cosmo, data)` and any likelihoods it calls can rely on `data` being in a consistent state, should they need it.
Therefore I have chosen to keep the updates for now, but it might be worth revisiting this decision for future developments or optimizations. But presumably, the overhead of these updates is minimal compared to the overall likelihood computation.

### `lkl_filter_module/likelihood_filter.py` module

#### `LikelihoodFilter` Class

The `LikelihoodFilter` class is designed to refine the samples generated during CONNECT’s iterative sampling by removing points with poor likelihood values relative to the best-fit model. This filtering step can be especially useful for trimming out the worst-performing points and focusing on the region of parameter space that yields higher likelihoods.

**Key Idea:**  
The filter works by comparing each point’s likelihood to that of the global best-fit point (the sample with the lowest `-log(likelihood)`, i.e., the highest likelihood). If a point’s likelihood is significantly worse than the best-fit—quantified by a user-defined `delta_chi2_threshold`—that point is discarded. However, the filter also ensures that a minimum number of points remain after filtering, preventing overly aggressive pruning.

**Core Steps in the Filtering Process:**

1. **Initialization and Setup**:  
   Upon instantiation, the `LikelihoodFilter` reads the relevant configuration parameters from the `param` object and sets up paths to various data files (e.g., `model_params.txt`, `likelihood_data.txt`). Depending on whether it is the initial sampling or a subsequent iteration (`iter_num`), the filter operates on the corresponding data folder. It also creates a dedicated `loglkl_discarded_data` subdirectory for storing points that fail the filtering criteria.

2. **Identifying the Best-Fit Point**:  
   The filter starts by examining `likelihood_data.txt`, which contains `-log(likelihood)` values for each sampled point. It finds the best-fit sample—the one with the lowest `-log(likelihood)`—and records its index and value. Using this information, it creates `best_fit_point.txt`, which includes the best-fit parameters and derived values.

3. **Determining Which Points to Discard**:  
   Next, the filter calculates the difference in χ² (`delta_chi2 = 2*(loglkl(point) - loglkl(best_fit))`) between each sample and the best-fit sample. Any point whose `delta_chi2` exceeds `delta_chi2_threshold` is a candidate for discarding.

   However, the filter enforces a `min_points_to_keep` threshold, ensuring that even if many points exceed the threshold, at least a certain minimum number of points remain. The code also allows for two strategies:
   - **Discard the worst first**: Sort points by their `delta_chi2` and discard the worst offenders first.
   - **Sequential discard**: Discard points in the order they appear in the file, stopping as soon as keeping the minimum number of points is threatened.

   By the end of this step, the filter has a list of indices corresponding to the points that must be removed.

4. **Applying the Filter to All Data Files**:  
   Once the discard indices are determined, the filter processes each data file line-by-line. For each file type:
   - The samples to discard are written to a corresponding file in the `loglkl_discarded_data` directory.
   - The original file is then overwritten with only the retained samples.

   This approach ensures that not only the parameter sets and likelihood values remain consistent, but also all related outputs—like CMB Cl power spectra (`Cl_output.txt`), matter power spectra (`Pk_output.txt`), background evolution files (`bg_output.txt`), or derived parameters (`derived.txt`)—are pruned accordingly. This keeps the entire dataset coherent and avoids data-point mismatches across different output files.

   The code carefully handles various file structures, including those for power spectra (`Pk` files), which have more complex formatting due to multiple redshift blocks.

5. **Output and Informational Messages**:  
   After filtering, the code prints summary information:
   - How many points were discarded.
   - How many points exceeded the threshold in total.
   - Whether the filtering stopped early to keep at least `min_points_to_keep` samples.
   - The current best-fit `-log(likelihood)` value.
   - The filtering strategy used.

**Rationale for Keeping the Filter Consistent**:  
By storing discarded samples separately and ensuring that all files remain synchronized, the filter helps maintain a clean and consistent dataset. This is particularly valuable in iterative approaches, where each new iteration relies on the pruned dataset from the previous one. The user-defined thresholds and strategies allow for a flexible tuning of how aggressively to filter, ensuring that the final dataset is both manageable and scientifically meaningful.

```python
    during iterative sampling in CONNECT. 
    The samples are filtered by:
    - Comparing the difference in chi-squared values between a point and the best-fit point.
    - Discarding points that exceed a specified threshold:
        if delta_chi2(point) > delta_chi2_threshold, the point is discarded.
    - Retaining a minimum number of points to avoid discarding too many points:
        if the number of points to retain is less than min_points_to_keep, the filter stops early.
        
    In short, the filter updates the training data files by:
    - saving the retained points (which meet the threshold) in the original files.
    - saving the discarded points in a separate subdirectory, loglkl_discarded_data, but with the same file names as the 
    original files.

    Parameters:
    - param: The parameter object from CONNNECT containing all input parameters, including filter settings, such as:
        - delta_chi2_threshold: The threshold for the difference in chi-squared values between a point and the best-fit 
        point.
        - min_points_to_keep: The minimum number of points to retain after filtering, to avoid discarding too many points.
        - discard_worst_first: If True, the filter will discard the worst points first. Otherwise, it will filter 
        sequentially, discarding older iteration points first.        
    - iter_num: The iteration number for which the filter is being applied. None for initial sampling.
    - CONNECT_PATH: Path to the root directory of the CONNECT data files.
    """
    
    
    def __init__(self, param, iter_num, CONNECT_PATH):
        """
        Initializes the LikelihoodFilter instance.

        Args:
            param: CONNECT configuration parameters, including filter settings.
            iter_num: Current iteration number; None for initial sampling.
            CONNECT_PATH: Path to the CONNECT working directory.
        """
        
        self.iter_num = iter_num
        self.param = param
        self.delta_chi2_threshold = self.param.delta_chi2_threshold
        self.min_points_to_keep = self.param.min_points_to_keep
        self.path = os.path.join(CONNECT_PATH, f'data/{self.param.jobname}')   
        if iter_num is None:
            self.iteration_path = os.path.join(self.path, f'N-{self.param.N}')
        else:
            self.iteration_path = os.path.join(self.path, f'number_{iter_num}')
        self.filtered_data_path = os.path.join(self.iteration_path, 'loglkl_discarded_data')
        self.model_params_file = os.path.join(self.iteration_path, 'model_params.txt')
        self.derived_file = os.path.join(self.iteration_path, 'derived.txt')
        self.likelihood_file = os.path.join(self.iteration_path, 'likelihood_data.txt')
        self.best_fit_file = os.path.join(self.iteration_path, 'best_fit_point.txt')
        self.N_samples = self.get_total_samples()
        self.min_points_reached = False
        
        # Create subdirectory to store the filtered data if it does not exist
        if not os.path.exists(self.filtered_data_path):
            os.makedirs(self.filtered_data_path)

    def run(self):
        """
        Executes the likelihood filtering process by:
        - Finding the best-fit value and index in likelihood_data.txt.
        - Creating the best_fit_point.txt file with the best-fit parameters and derived values.
        - Finding the indices of points that do not meet the threshold, "discarded_indices".
        - Filtering each type of file based on the discard indices:
            - model_params.txt, derived.txt, Cl_output.txt, Pk_output.txt, bg_output.txt, th_output.txt, extra_output.txt, likelihood_data.txt.
        - Print statements to update the user on the filtering process.        
        """
        
        best_fit_loglkl, best_fit_index = self.find_best_fit_loglkl()
        self.create_best_fit_file(best_fit_loglkl, best_fit_index)
        
        # Find the indices of points that do not meet the threshold
        discard_indices, total_potential_discard = self.find_discard_indices(best_fit_loglkl)
        
        # Filter each type of file based on discard indices
        self.filter_data('model_params.txt', discard_indices, Pk=False, no_header=False)
        
        if len(self.param.output_derived) > 0:
            self.filter_data('derived.txt', discard_indices, Pk=False, no_header=False)          
        
        for output in self.param.output_Cl:
            self.filter_data(f'Cl_{output}.txt', discard_indices, Pk=False, no_header=False)
        
        for output in self.param.output_Pk:
            self.filter_data(f'Pk_{output}.txt', discard_indices, Pk=True, no_header=False)

        """ # Commented out for now, as I encountered a case where one of the bg files was missing.       
        for output in self.param.output_bg:
            output = output.replace('/', '\\')
            self.filter_data(f'bg_{output}.txt', discard_indices, Pk=False, no_header=False)
        """
        
        for output in self.param.output_bg:
            output = output.replace('/', '\\')
            filename = f'bg_{output}.txt'
            original_file = os.path.join(self.iteration_path, filename)
            
            if os.path.exists(original_file):
                self.filter_data(filename, discard_indices, Pk=False, no_header=False)
            else:
                print(f"Debug: {filename} does not exist and will be skipped for filtering.")

        
        for output in self.param.output_th:
            self.filter_data(f'th_{output}.txt', discard_indices, Pk=False, no_header=False)
        
        for output in self.param.extra_output:
            self.filter_data(f'extra_{output}.txt', discard_indices, Pk=False, no_header=True)
        
        self.filter_data('likelihood_data.txt', discard_indices, Pk=False, no_header=False)
        
        
        num_filtered = len(discard_indices)
        iteration = f"iteration {self.iter_num}" if self.iter_num is not None else "initial sampling"
        formatted_best_fit = f"{best_fit_loglkl:.4f}"         
        filter_method = (
            "Discarded worst points first."
            if self.param.discard_worst_first
            else "Filtered sequentially, discarding older iteration points first."
        )

        # Print statements
        if self.min_points_reached:
            print(
                f"Likelihood filter discarded {num_filtered}/{self.N_samples} points in {iteration}. "
                f"Stopped early to retain ≥{self.min_points_to_keep} points. "
                f"{total_potential_discard} exceeded threshold; {num_filtered} discarded. "
                f"{filter_method} Current global best_fit_loglkl: {formatted_best_fit}.",
                flush=True
            )
        else:
            print(
                f"Likelihood filter discarded {num_filtered}/{self.N_samples} points in {iteration}. "
                f"{total_potential_discard} exceeded threshold. "
                f"{filter_method} Current global best_fit_loglkl: {formatted_best_fit}.",
                flush=True
            )
    
    def find_best_fit_loglkl(self):
        """ Finds and returns the minimum -log(likelihood) value and its index in likelihood_data.txt. 
        This corresponds to the -log(likelihood) value of the current global best-fit point.
        """
        likelihood_values = []
        with open(self.likelihood_file, 'r') as f:
            for line in f:
                if not line.startswith('#'):
                    # Split the line into columns
                    columns = line.strip().split('\t')
                    # Extract the first column as the likelihood value
                    loglkl_value = float(columns[0])
                    likelihood_values.append(loglkl_value)

        best_fit_loglkl = min(likelihood_values)
        best_fit_index = likelihood_values.index(best_fit_loglkl)
        return best_fit_loglkl, best_fit_index

    def create_best_fit_file(self, best_fit_loglkl, best_fit_index):
        """ Creates the best_fit_point.txt file using the best-fit "true" likelihood value and index. 
        This file contains the calculated -log(likelihood) value, the model input parameters, and the derived values.
        """
        
        # Retrieve headers from model_params.txt and derived.txt
        with open(self.model_params_file, 'r') as f:
            model_params_header = f.readline().strip().lstrip('#').strip().split('\t')
        if len(self.param.output_derived) > 0:
            with open(self.derived_file, 'r') as f:
                derived_header = f.readline().strip().lstrip('#').strip().split('\t')

        # Combine headers with loglkl as the first entry
        if len(self.param.output_derived) > 0:
            full_header = '# ' + '\t'.join(['loglkl'] + model_params_header + derived_header)
        else:
            full_header = '# ' + '\t'.join(['loglkl'] + model_params_header)
        
        # Retrieve the best-fit parameters and derived values
        with open(self.model_params_file, 'r') as f:
            model_params_lines = f.readlines()
            best_fit_params = model_params_lines[best_fit_index + 1].strip().split('\t')

        if len(self.param.output_derived) > 0:
            with open(self.derived_file, 'r') as f:
                derived_lines = f.readlines()
                best_fit_derived = derived_lines[best_fit_index + 1].strip().split('\t')

        # Combine the best-fit data with the likelihood value as the first entry
        if len(self.param.output_derived) > 0:
            best_fit_data = [str(best_fit_loglkl)] + best_fit_params + best_fit_derived
        else:
            best_fit_data = [str(best_fit_loglkl)] + best_fit_params

        # Write the combined header and best-fit data to `best_fit_point.txt`
        with open(self.best_fit_file, 'w') as f:
            f.write(full_header + '\n')
            f.write('\t'.join(best_fit_data) + '\n')

    
    def find_discard_indices(self, best_fit_loglkl):
        """
        Identifies indices of points to discard based on the Δχ² threshold:
            if Δχ²(point) > Δχ²_threshold, the point's index is added to the discard_indices list.
            as long as the number of points to retain is greater than min_points_to_keep.
        
        Parameters:
        - best_fit_loglkl: The global best-fit -log(likelihood) value.
        Returns:
        - discard_indices: Indices of points that exceed the Δχ² threshold.
        - total_potential_discard: Total number of points that exceed the threshold, for informational purposes when 
        printing.
            it's the number of points that could be discarded if the minimum number of points to retain was 0.
        Additional Attributes:
        - min_points_to_keep: The minimum number of points to retain after filtering, to avoid discarding too many points.
        - min_points_reached: A flag indicating whether the minimum number of points to retain has been reached. Only 
        used for informational purposes for printing.
        - discard_worst_first: If True, the filter will discard the worst points first. Otherwise, it will filter 
        sequentially, discarding older iteration points first.
        - delta_chi2_threshold: The threshold for the difference in chi-squared values between a point and the best-fit 
        point.
        """
        
        """
        In summary, this function:
        1. Reads the likelihood values from the likelihood_data.txt file.
        2. Calculates the delta_chi2 value for each data point.
        3. Sorts the delta_chi2 values from worst to best (if discard_worst_first is True).
        4. Filters out points that do not meet the threshold, while retaining a minimum number of points.
        It also counts the total number of points that exceed the threshold, which is used for informational purposes.
        5. Returns the indices of points to discard and the total number of points that exceed the threshold.
        """
        
        
        likelihood_values = []
        header_count = 0

        # Read likelihood values from the likelihood_data.txt file
        with open(self.likelihood_file, 'r') as f:
            for idx, line in enumerate(f):
                if line.startswith('#'):
                    header_count += 1 # Count header lines (likelihood_data.txt has 1 header line)
                    continue  

                # Split the line into columns, first column is "true" -log(likelihood) value. 2nd column is "fake" -log(likelihood) value.
                columns = line.strip().split('\t')
                # Extract the first column as the likelihood value
                loglkl_value = float(columns[0])
                data_index = idx - header_count  # Adjust for header lines
                likelihood_values.append((data_index, loglkl_value))

        # Calculate delta_chi2 for each data point (Δχ² = 2 * (loglkl - best_fit_loglkl))
        # Stores the index and delta_chi2 value for each data point. The index corresponds to sample's position across all original data files.
        delta_chi2_values = [
            (idx, (loglkl - best_fit_loglkl) * 2) for idx, loglkl in likelihood_values
        ]

        
        if self.param.discard_worst_first:
            # Sort from highest to lowest delta_chi2 (worst to best)
            delta_chi2_values.sort(key=lambda x: x[1], reverse=True)
        else:
            # Keep the original order (as read from the file), i.e. sequential order.
            pass  # No action needed since delta_chi2_values are already in original order

        # Filter out points that do not meet the threshold
        discard_indices = [] # List to store indices of points that will be discarded
        total_potential_discard = 0  # Count points that exceed the threshold
        for idx, delta_chi2 in delta_chi2_values:
            if delta_chi2 > self.delta_chi2_threshold:
                total_potential_discard += 1 
                
                # Check if discarding this point would still retain the minimum required points
                if (self.N_samples - len(discard_indices)) > self.min_points_to_keep:
                    discard_indices.append(idx)
                else:
                    # Stop adding to discard_indices to ensure we retain enough points, but continue counting potential discards
                    self.min_points_reached = True #Used for informational purposes only
            else:
                # If data is sorted, stop early since all subsequent points are within the threshold
                if self.param.discard_worst_first:
                    break  # Only applicable if sorted; else continue
                # If not sorted, we still need to check all points
                continue

        return discard_indices, total_potential_discard


    def filter_data(self, filename, discard_indices, no_header=False, Pk=False):
        """
        Filters data in a file by copying discarded points to a subdirectory and removing them from the main file.
        Handles different structures for regular files and Pk files.

        Args:
            filename: Name of the file to filter.
            discard_indices: List of indices corresponding to points to be discarded.
            no_header: If True, indicates that the file does not contain a header row (e.g., extra_output.txt).
            Pk: If True, indicates that the file has a specific format for P(k) data.
        """
        original_file = os.path.join(self.iteration_path, filename) # Original file path
        filtered_file = os.path.join(self.filtered_data_path, filename) # Filtered file path

        # Read all lines in the original file
        with open(original_file, 'r') as f:
            lines = f.readlines() # Read all lines in the original file

        if not Pk:
            # Process non-Pk files
            start_idx = 1 if not no_header else 0   # Skip header if present

            # Write discarded points to the filtered file
            with open(filtered_file, 'w') as f_discarded:
                if not no_header:
                    f_discarded.write(lines[0])  # Copy header if it exists
                for idx in discard_indices:
                    f_discarded.write(lines[idx + start_idx])

            # Write non-discarded points back to the original file
            with open(original_file, 'w') as f:
                if not no_header:
                    f.write(lines[0])  # Retain header if it exists
                for i, line in enumerate(lines[start_idx:], start=start_idx):
                    if i - start_idx not in discard_indices: # Skip discarded points
                        f.write(line)

        else:           
            """
            Handle P(k) files with a specific structure
            
            P(k) File Structure:
            ---------------------
            1. **Header Line**: The first line contains k-values, common across all redshifts.
            2. **Redshift Header**: Each block starts with a line like `# z = <redshift_value>`, indicating the redshift.
            3. **Data Rows**: Following the redshift header, there are `N_samples` rows of power spectrum values,
               one row per sample, with one value for each k-value.
            4. **Repeating Blocks**: This pattern (redshift header + data rows) repeats for each redshift in the file.
            ---------------------
            
            # - Discarded samples are handled per redshift block.
            """
            
            with open(filtered_file, 'w') as f_discarded, open(original_file, 'w') as f:
                # Write the k-values header to both discarded and retained files
                f.write(lines[0])
                f_discarded.write(lines[0])

                line_idx = 1  # Start processing after the k-values header

                """
                This block processes the P(k) file by iterating through the original file stored lines, line by line, 
                starting after the k-values header.
                It identifies redshift headers and processes data rows associated with each redshift block, by:
                - Writing the redshift header to both files, discarded and retained file
                - iterating over all the next `N_samples` lines, writing each line to the appropriate file.
                - If the sample index is in `discard_indices`, the sample is written to the filtered file.
                - Otherwise, the sample is written to the original file.
                - The current line index is continually updated to keep track of the current position in the original 
                file.
                such that by the end of the loop, it should be at the next redshift header or the end of the file.
                """

                while line_idx < len(lines): # Iterate through all lines in the file
                    # Identify the redshift header, which begins a new block of data
                    if lines[line_idx].startswith('# z ='):
                        z_header = lines[line_idx] 
                        f.write(z_header) 
                        f_discarded.write(z_header)
                        line_idx += 1 # Move to the next line

                        # Process data rows associated with this redshift block
                        for sample_idx in range(self.N_samples): # Iterate over all samples
                            if line_idx >= len(lines):
                                break # Stop if we reach the end of the file
                            line = lines[line_idx] 
                            
                            if sample_idx in discard_indices:
                                f_discarded.write(line) # Write discarded sample to the filtered file
                            else:
                                f.write(line) # Write retained sample to the original file
                            line_idx += 1 #Keep track of the current line index. 
                            # By the end of the loop, it should be at the next redshift header or the end of the file.
                    else:
                        # Handle unexpected lines (should not occur in properly formatted Pk files)
                        line_idx += 1

    def get_total_samples(self):
        """ Determine the total number of samples based on the length of the likelihood_data.txt file. """
        with open(self.likelihood_file, 'r') as f:
            return sum(1 for line in f if not line.startswith('#'))
```
